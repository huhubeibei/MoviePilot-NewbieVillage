# 点一下弹个 Not Found？一次跨层排查记

## 现象

插件页面点某个按钮，右下角弹出红色「Not Found」，但页面上其他功能全部正常——数据能加载、接口都 200。

## 排查

1. **看服务器日志**：MP 的容器日志里找到了那条 404 请求的完整路径——是一个**裸的 API 根路径**，参数全空。
2. **抓请求发起者**：浏览器 F12 → Network → 点那条 404 → 看「启动器」显示的 JS 文件和行号，定位到发出请求的确切代码。
3. **分层验证**：换无痕窗口复现（排除缓存）、用一个全新账号复现（排除用户数据）——两次都能复现，说明是**确定性的代码行为**而不是缓存或权限问题。

## 结论

- 根因：不同页面上，宿主传给插件前端的 `api` 参数**形态不一样**（有时是完整的接口对象，有时是一个绑定了默认行为的函数）。代码把函数形态当对象用，无意间触发了一次空参数请求。
- 修复思路：**不盲目调用形态不明的参数**，统一走宿主暴露的全局接口实例做兜底。
- 教训：**前端改动后要做 DOM 级验证**，只看网络请求 200/404 会漏掉渲染层的问题；反过来，只看渲染不看请求也会漏掉这类幽灵调用。

## 关联设置

- **浏览器调试**：F12 → Network 看请求与启动器；Application → 清除站点数据解决顽固缓存
- **插件更新**：市场里点更新即可拿到修复版本
